## 4. 闸门 —— 以及它照不到的地方

**唯一本机入口 = `cargo xtask ci`**（fmt → clippy → `cargo test --locked` → `parity-check` → `recount`，五段）。

```bash
cargo xtask ci                                   # 五段
cargo xtask --help                               # 全部子命令
OPENBOT_UPSTREAM_DIR=… cargo xtask recount --require-upstream    # 143/143
OPENBOT_TEST_DATABASE_URL=… cargo test -p openbot-infra --all-features -- --include-ignored   # 真库
cargo deny check                                 # advisories / bans / licenses / sources 四段
```

### 4.1 CI 从来没有跑过一次

```bash
gh api repos/acosmi/OpenBot/actions/runs --jq '.total_count'   # 0
```

正向对照：同一条命令在一个 CI 正常运行的仓上返回四位数，所以**不是命令查不到**，是真的 0 次。
`.github/workflows/ci.yml` 存在，但自动触发（`push` / `pull_request`）在 2026-08-22 因 Actions 额度耗尽被**注释保留**，
只剩 `workflow_dispatch`。要跑就手动派发：

```bash
gh workflow run ci.yml --repo acosmi/OpenBot --ref <分支>
```

**后果：本机闸门是唯一的闸门。** `CLAUDE.md` §10 的实跑清单从"合并前的双保险"变成"唯一保险"，一条都不能省。
另：**CONFLICTING 的 PR 一条 CI 都不会跑**（GitHub 算不出 `refs/pull/N/merge`），而 `gh pr checks` 显示
"no checks reported" —— 与"还没开始"不可区分。先把 base 并进分支让 mergeable 变绿，再派发。

### 4.2 recount 会**静默少跑 81 条**

不设 `OPENBOT_UPSTREAM_DIR` 时，143 条判据里只跑 62 条，另外 81 条（`cwd: upstream` 的那些）被跳过 ——
**而 `cargo xtask ci` 照样 exit 0**。xtask 是诚实的：它会打印「跳过明细（81 条，全部因为 OPENBOT_UPSTREAM_DIR
未设置；这些判据本轮**没有被验证**）」并按台账文件分组列出。**请读那段输出，不要只看 exit code。**

| 跑法 | 结果 |
| --- | --- |
| `cargo xtask recount`（无上游克隆） | 通过 62 / 失配 0 / **跳过 81**（共 143） |
| `OPENBOT_UPSTREAM_DIR=… cargo xtask recount --require-upstream` | 通过 **143** / 失配 0 / 跳过 0 |

`--require-upstream` 会把"跳过"直接判红。**建议把它设成常态**，理由就是上面这条：一条不跑的判据和一条通过的判据，
在 exit code 上长得一模一样。

### 4.3 `cargo deny check` 的 advisories 段现在是**红**的

移交时实测：`advisories FAILED, bans ok, licenses ok, sources ok`（exit 1）。

- 命中 **RUSTSEC-2023-0071**（Marvin 计时侧信道），`rsa 0.9.10` ← `openidconnect 4.0.1` ← `openbot-infra`。
- 上游 advisory 明写 **"No safe upgrade is available!"**。
- `rsa` 是 `openidconnect 4.0.1` 的**非可选依赖**（`cargo tree -p openidconnect -e features --depth 1` 里
  `rsa feature "default"` 恒在），已经钉了 `default-features = false` 也去不掉。
- 本仓的用法是 **RP 侧验签**：`grep -rn 'RsaPrivateKey\|PrivateSigningKey' --include=*.rs crates/` **零命中**，
  而同一条 grep 找我们确实用到的符号（`openidconnect::` 在 11 个文件里）能命中 —— 也就是说
  漏洞要求的"攻击者可观测**私钥**运算耗时"这条前提，在本仓的调用面上不成立。
- **但这不是可以忽略它的理由，只是可以给出结论的依据。** 这条要一次记录在案的裁决，见 §8 的 D-1。

> 我上一批只跑了 `cargo deny check bans` 与 `licenses` 两段并报了"ok"。那句话对那两段成立，
> 对 CI 实际会跑的 `cargo deny check`（四段）不成立。在此更正。

### 4.4 CI 的 `gates` job 与本机 `cargo xtask ci` **不是同一份清单**

`.github/workflows/ci.yml` 两个 job：`gates`（fmt / clippy / `cargo test --locked` / `xtask parity-check`）
与 `supply-chain`（`cargo deny check` + `cargo audit --deny warnings`，由 `run_supply_chain` input 开关）。

**`gates` 里没有 recount 段。** 也就是说即便哪天 CI 恢复自动触发，143 条复算判据也只有本机会跑。
另一方向上，`cargo deny` / `cargo audit` / `cargo vet` / OSV / secret scan / license-NOTICE-provenance /
SBOM / 可复现构建 / 签名校验**刻意不在 `xtask ci` 里** —— 源码注释写明理由：它们各自缺一份本仓尚不存在的基线，
塞进来就是恒红闸门。workflow 尾部逐条列了这 7 条尚未接线的闸门与各自的解除条件。

**结论：两边都要跑，谁也不是谁的超集。**

## 5. 台账现状（这是"还剩多少活"的唯一量化口径）

`parity/*.yaml` 九份 + `fixtures/MANIFEST.yaml` 一份。**权威计数口径是 `cargo xtask parity-check --json`**，
不要手写 grep —— 理由见下面的引号坑。

| 台账 | 条目 | 已闭合 | 未闭合 |
| --- | ---: | ---: | ---: |
| `parity/api.yaml` | 148 | 4 | 144 |
| `parity/browser-operations.yaml` | 46 | 0 | 46 |
| `parity/components.yaml` | 22 | 0 | 22 |
| `parity/env.yaml` | 71 | 35 | 36 |
| `parity/events.yaml` | 73 | 0 | 73 |
| `parity/routes.yaml` | 32 | 0 | 32 |
| `parity/tables.yaml` | 53 | 41 | 12 |
| `parity/tests.yaml` | 1047 | 0 | 1047 |
| `parity/ui.yaml` | 152 | 0 | 152 |
| **parity 合计** | **1644** | **80** | **1564** |
| `fixtures/MANIFEST.yaml`（单列，不计入 parity） | 28 | 6 | 22 |

`done + todo = 1644 = entries`，也就是说**没有第三种状态漏在外面**（`in_progress` 是合法值但全仓零使用）。

> **引号坑（会让你算错，而且不会报错）**：三种写法并存 —— `status: todo`（裸）、`status: "todo"`（双引号）、
> `status: 'todo'`（单引号，只有 `events.yaml` 这么写）。任何只覆盖其中一两种的 grep 都会静默少算。
> 我第一次复算就漏掉了 `events.yaml` 那 73 条。引号无关的写法：

```bash
cargo xtask parity-check --json        # 权威口径，优先用这条

# 手算时的引号无关判据（done + todo 必须等于 entries，等不上说明有条目没分类）
python3 -c "
import glob,re,io
E=D=T=0
for f in sorted(glob.glob('parity/*.yaml')):
    s=io.open(f,encoding='utf-8').read()
    E+=len(re.findall(r'^  - id: ',s,re.M))
    D+=len(re.findall(r'''^\s+status: ['\"]?done['\"]?\s*$''',s,re.M))
    T+=len(re.findall(r'''^\s+status: ['\"]?todo['\"]?\s*$''',s,re.M))
print('entries',E,'done',D,'todo',T,'done+todo',D+T)
"   # entries 1644 done 80 todo 1564 done+todo 1644
```

`tests.yaml` 的 1047 条是 `cargo xtask test-inventory --upstream <路径>` 用 AST 解析上游测试文件生成的
（105 个文件 / 229 个 describe / 1047 个 test case），不是手写的。它是 G8 判据「Phase 0 AST 级 test inventory
mapping 100%」的对象 —— 也就是说这 1047 条最终都要有归宿，但**不是这一批的活**。

## 9. 会咬人的十七条

1. **改 CEL 策略面之前先读 R27。** `cel 0.14.3` 的解析器会爆栈，而 Rust 的栈溢出是 **abort 不是可捕获的 panic**。
   首崩深度随线程栈线性变化（约 1 MiB=6 层 / 2 MiB=12 / 4 MiB=28 / 8 MiB=64 / 64 MiB 不崩）——
   也就是说**同一条表达式的成败取决于它跑在哪个线程上**。防线是解析前的非递归闸门（≤ 4096 字节、≤ 8 层嵌套）
   加上把解析放进自建 16 MiB 栈的线程。**求值不需要也不能这么做**（求值在工具调用热路径上）。
2. **收紧不等于更安全。** R33：`KEY_ENCRYPTION_KEY` 硬要求 32 字节，会让 16/24 字节 KEK 的部署起不来，
   于是**永远迁不出自己的密文**。收紧任何"看起来太松"的校验之前，先问一句：**被收紧的那批数据还出得来吗？**
3. **`cargo fmt -p <crate> -- --check` 有盲区。** 当 crate 里有无法解析的 `mod`（文件还没建）时，
   它只检查 `tests/` 作用域。它并不静默 —— 会打印 `failed to resolve mod` 并 exit 1 ——
   但 `grep '^Diff in'` 这种判法会把它读成"`src/` 全干净"。**两类行都要看。**
4. **xtask 驱动器必须建在 `target-xtask/`**（`.cargo/config.toml` 的 alias 已经配好 `--target-dir`）。
   与子构建的 `target/` 互不包含：否则第 3 步会去重链正在运行的驱动器自己，Windows 报
   `os error 5` **恒红**、Linux **恒绿**。摆错了 `cmd_ci` 会当场拒跑并打印两条路径。
5. **`trim()` 在 JS 和 Rust 不是同一个函数**（R30）。JS 的 WhiteSpace 含 U+FEFF，Rust 的 `str::trim` 不含。
   带 BOM 的 `.env` 会让 `INITIAL_ADMIN_EMAILS` 首项永远匹配不上、**admin floor 静默失效**，而且锁死之后没有回来的路。
6. **"期望 0 / 不存在 / 被拒绝"的断言必须配正向对照。** 否则它在"这个功能压根没实现"的世界里同样为真。
   本仓已有的范式：`fixtures/db/README.md` 的三行断言表、`cel_corpus_parity` 的 `evaluated == 69`。
7. **`#[ignore]` 的用例不是闸门，但跳过必须可见。** 真库 harness 在 `--include-ignored` 下**硬失败**而不是
   静默放行 —— 因为显式加了那个 flag 就是在说"我要跑真库测试"，此时静默通过会让"我跑了集成测试且全绿"变成假话。
8. **schema 只许 expand。** 禁 drop / rename / 类型收紧 / 主键改写，无 downgrade migration（v3 §14.3）。
9. **本仓 public。** 写进仓库的每一行文字都不得含私有上游的内部路径、错误字符串字面量、私有 URL、凭据
   或本机口令。提交前扫一遍，并且**给扫描配一个能命中的正向对照**，否则你只是证明了 grep 没打错字。
10. **本机的 `git ls-remote` / `cargo deny` 拉 advisory-db 会偶发 `schannel: failed to receive handshake`。**
    那是瞬态，重试即可；**拿到空值时先看值再下判定**，不要据此判 DIFFERS 或 NO。
11. **判红之前先排除环境因素。** 并发跑闸门时会有一批用例红在**恰好等于自己超时预算**的耗时上；
    耗时 ≈ 预算就单跑复核，争用下的耗时不构成回归证据。
12. **`gh pr checks` 分不清"没跑"和"没配"。** 见 §4.1。
13. **台账计数的三种引号形态**会让手写 grep 静默少算。权威口径 `cargo xtask parity-check --json`，见 §5。
14. **`#[ignore]` 的 grep 要锚行首**：`grep -rn '#\[ignore'` 得 28（误中文档注释里的散文），
    `grep -rnE '^\s*#\[ignore'` 得 **22**（真实属性数）。
15. **台账 `status: done` 不蕴含"东西已经存在"。** `parity/tables.yaml` 的 13 条 migration 全是 `done`，
    但 `db::migrations` 模块**不该存在**；28 张表的行结构是 `done`，但 40 个 `repo=` 落点里 39 个还没写。
    台账顶部注释对此有逐字说明 —— **读注释，别只读 status**。
16. **靠 grep 关键字找不到"还有什么没做"。** 全仓 `todo!()` / `unimplemented!()` / `FIXME` **零命中**，
    `TODO` 只有 1 处（在一个 css 文件里）。留白是**声明在各 crate `lib.rs` 的模块文档里**的
    （「**尚未实现**（不要在这里找）：…」），配合台账的 `status` 使用。要盘缺口就读那两处。
17. **`cargo xtask tools fetch` / `tools verify` 还不存在。** `tools/pins.toml` 提到它们，但 `xtask.rs::main`
    的 match 里没有 `tools` 分支，未知子命令会报错退出。要用钉 sha256 的构建期二进制（GUI 阶段）得先把它实现出来。

## 10. 这套东西是怎么被造出来的（可选，但推荐照抄）

Phase 0 / G1 / G2 都是**一个主控 + 若干子代理**按波次推进的，纪律照抄 `CLAUDE.md` §8 与 §11：

- **子代理只写码、不碰 git**（不 commit、不 push、不切分支）。git 全部动作由主控做，避免半成品互相覆盖。
- **子代理的结论主控必须亲自复核，并在其结论上再向下追一层**：引用的位置亲读、计数亲算、
  "已接线 / 存在"追到调用链或测试证据。矛盾以亲测为准。
- **给子代理的"事实"也要先跑命令。** 这一批里主控被子代理纠正过三次，三次都是主控凭印象给了错的前提
  （一次是常量个数，一次是"本机没装 node/bun"，一次是一个加密算法的可用密钥长度）。
  错的前提会被子代理当作约束照做，代价比错的结论更大。
- **一波一件事**；每波开工前把范围片段直接给出去，不让子代理去读长文档（`CLAUDE.md` 是唯一例外，必读）。
