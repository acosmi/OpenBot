### 4.4 CI 的 `gates` job 与本机 `cargo xtask ci` **不是同一份清单**

`.github/workflows/ci.yml` 两个 job：`gates`（fmt / clippy / `cargo test --locked` / safe-dialer guard / SAML/xmlsec guard / `xtask parity-check`）
与 `supply-chain`（R44 guard + GUI dependency guard + `cargo deny check` + 显式三 ID 的 `cargo audit` +
`cargo vet --locked`，

**`gates` 里没有 recount 段。** 也就是说即便哪天 CI 恢复自动触发，158 条复算判据也只有本机会跑。
另一方向上，`cargo deny` / `cargo audit` / `cargo vet` / OSV / secret scan / license-NOTICE-provenance /
SBOM / 可复现构建 / 签名校验**刻意不在 `xtask ci` 里**：它们需要独立工具、
审计数据或发行产物，不是纯 Cargo 源码闸门。
其中 deny/audit/vet 已在 `supply-chain` job 接线，但仍不进 `xtask ci`（需审计库/锁文件与独立工具）。
workflow 尾部逐条列了剩余 6 条尚未接线闸门与各自的解除条件。

**结论：两边判据并非超集关系；但 R63 当前只授权本机定向测试。外部 Actions 与完整 `xtask ci`
必须等用户重新授权后才能运行。**

```bash
cargo xtask parity-check --json        # 权威口径，优先用这条

# 手算时的引号无关判据（done + todo 必须等于 entries，等不上说明有条目没分类）
python3 -c "
import glob,re,io
E=D=T=0
for f in sorted(glob.glob('parity/*.yaml')):
    s=io.open(f,encoding='utf-8').read()
    E+=len(re.findall(r'^  - id: ',s,re.M))
    D+=len(re.findall(r'''^\s+status: ['\"]?done['\"]?\s*$''',s,re.M))
    T+=len(re.findall(r'''^\s+status: ['\"]?todo['\"]?\s*$''',s,re.M))
print('entries',E,'done',D,'todo',T,'done+todo',D+T)
"   # entries 1694 done 702 todo 992 done+todo 1694
```

## 9. 会咬人的二十条

1. **改 CEL 策略面之前先读 R27。** `cel 0.14.3` 的解析器会爆栈，而 Rust 的栈溢出是 **abort 不是可捕获的 panic**。
   首崩深度随线程栈线性变化（约 1 MiB=6 层 / 2 MiB=12 / 4 MiB=28 / 8 MiB=64 / 64 MiB 不崩）——
   也就是说**同一条表达式的成败取决于它跑在哪个线程上**。防线是解析前的非递归闸门（≤ 4096 字节、≤ 8 层嵌套）
   加上把解析放进自建 16 MiB 栈的线程。**求值不需要也不能这么做**（求值在工具调用热路径上）。
2. **收紧不等于更安全。** R33：`KEY_ENCRYPTION_KEY` 硬要求 32 字节，会让 16/24 字节 KEK 的部署起不来，
   于是**永远迁不出自己的密文**。收紧任何"看起来太松"的校验之前，先问一句：**被收紧的那批数据还出得来吗？**
3. **`cargo fmt -p <crate> -- --check` 有盲区。** 当 crate 里有无法解析的 `mod`（文件还没建）时，
   它只检查 `tests/` 作用域。它并不静默 —— 会打印 `failed to resolve mod` 并 exit 1 ——
   但 `grep '^Diff in'` 这种判法会把它读成"`src/` 全干净"。**两类行都要看。**
4. **xtask 驱动器必须建在 `target-xtask/`**（`.cargo/config.toml` 的 alias 已经配好 `--target-dir`）。
   与子构建的 `target/` 互不包含：否则第 3 步会去重链正在运行的驱动器自己，Windows 报
   `os error 5` **恒红**、Linux **恒绿**。摆错了 `cmd_ci` 会当场拒跑并打印两条路径。
5. **`trim()` 在 JS 和 Rust 不是同一个函数**（R30/R51）。JS 含 U+FEFF、Rust 不含；Rust 又多认
   JS 不认的 U+0085。带 BOM 的 `.env` 会让 admin floor 静默失效；反向多裁 U+0085 会擅自扩大身份等价类。
   所有上游 TrimString 对齐路径只许复用 `openbot_domain::text`。
6. **"期望 0 / 不存在 / 被拒绝"的断言必须配正向对照。** 否则它在"这个功能压根没实现"的世界里同样为真。
   本仓已有的范式：`fixtures/db/README.md` 的三行断言表、`cel_corpus_parity` 的 `evaluated == 69`。
7. **`#[ignore]` 的用例不是闸门，但跳过必须可见。** 真库 harness 在 `--include-ignored` 下**硬失败**而不是
   静默放行 —— 因为显式加了那个 flag 就是在说"我要跑真库测试"，此时静默通过会让"我跑了集成测试且全绿"变成假话。
8. **schema 只许 expand。** 禁 drop / rename / 类型收紧 / 主键改写，无 downgrade migration（v3 §14.3）。
9. **本仓 public。** 写进仓库的每一行文字都不得含私有上游的内部路径、错误字符串字面量、私有 URL、凭据
   或本机口令。提交前扫一遍，并且**给扫描配一个能命中的正向对照**，否则你只是证明了 grep 没打错字。
10. **本机的 `git ls-remote` / `cargo deny` 拉 advisory-db 会偶发 `schannel: failed to receive handshake`。**
    那是瞬态，重试即可；**拿到空值时先看值再下判定**，不要据此判 DIFFERS 或 NO。
11. **判红之前先排除环境因素。** 并发跑闸门时会有一批用例红在**恰好等于自己超时预算**的耗时上；
    耗时 ≈ 预算就单跑复核，争用下的耗时不构成回归证据。
12. **`gh pr checks` 分不清"没跑"和"没配"。** 见 §4.1。
13. **台账计数的三种引号形态**会让手写 grep 静默少算。权威口径 `cargo xtask parity-check --json`，见 §5。
14. **`#[ignore]` 的 grep 要锚行首**：W-5 batch 7 后真实属性数是 **109**（batch 6 的 102 上新增 7 条 PG package sync；loader 那条默认运行）；裸搜仍会误中文档注释里的散文。
15. **台账 `status: done` 不蕴含"东西已经存在"。** `parity/tables.yaml` 的 13 条 migration 全是 `done`，
    但 `db::migrations` 模块**不该存在**；28 张表的行结构是 `done`，但 40 个 `repo=` 落点里 39 个还没写。

## 10. 这套东西是怎么被造出来的（可选，但推荐照抄）

Phase 0 / G1 / G2 都是**一个主控 + 若干子代理**按波次推进的，纪律照抄 `CLAUDE.md` §8 与 §11：

- **子代理只写码、不碰 git**（不 commit、不 push、不切分支）。git 全部动作由主控做，避免半成品互相覆盖。
- **子代理的结论主控必须亲自复核，并在其结论上再向下追一层**：引用的位置亲读、计数亲算、
  "已接线 / 存在"追到调用链或测试证据。矛盾以亲测为准。
- **给子代理的"事实"也要先跑命令。** 这一批里主控被子代理纠正过三次，三次都是主控凭印象给了错的前提
  （一次是常量个数，一次是"本机没装 node/bun"，一次是一个加密算法的可用密钥长度）。
  错的前提会被子代理当作约束照做，代价比错的结论更大。
- **一波一件事**；每波开工前把范围片段直接给出去，不让子代理去读长文档（`CLAUDE.md` 是唯一例外，必读）。
