## 2. 选择边界

- 空 actor 在查询前返回稳定 `mcp_user_actor_required`，不能命中“排序第一条”连接；
- 个人凭据只按 `(server_id, actor_id)` 查找，deployment OAuth client 永远不作为个人 token fallback；
- join 指向的行还必须同时满足 `kind=mcp_user_token`、`provider=server_id`、
  `key_id=actor_id`、`revoked_at IS NULL`；deployment 行必须是同 server 的
  `mcp_oauth_client`；错绑定归存储损坏，不猜修复；
- `CredentialRecordVault` 对 `credentials.encrypted_value` 兼容读固定上游 v1、读写 v2 六元组
  AAD；与 SSO 不同，credentials 历史明文没有合法来源，明确拒绝；
- refresh token 只进入 `OAuthRefreshExchange`。token endpoint 返回值与 refresh 常数时间相等时，
  稳定拒绝 `oauth_refresh_token_passthrough_refused`，因此拿不到可交给 vendor 的
  `VendorAccessToken`；
- 本批不实现 token endpoint、RMCP、Drive 或 vendor tool response。那些仍属于 G4，不能用
  injected fake runtime 冒充。

## 3. 人员移除与孤儿退役

People 的 deny/session/auth-generation/audit 事务先提交；随后经 application-owned
`OwnedCredentialRetirer` 执行第二阶段。这样 credential/audit 故障不会把已经生效的人员移除
回滚。重试一次相同的 `revoked=true` 即使 people 状态未变化，也会再次执行幂等第二阶段。

退役器不沿可能已消失的 `mcp_user_credentials` 查 owner，而直接以
`credentials.kind='mcp_user_token' AND key_id=owner` 找全部 active 行。每批在一个 PostgreSQL
事务里完成：

1. 把全部命中行写成 `revoked_at` 非空；
2. 删除该 owner 的残留 join；
3. 每条追加 `mcp.account_disconnected` hash-chain audit；
4. 任一步失败整体回滚本次 credential 退役。

审计 payload 只新增三个 typed allowlist 字段：`credential_owner`、`revocation_reason`、
`vendor_revoked`。本地退役明确记录 `vendor_revoked=false`，不把“部署已不再持有 secret”误写成
“vendor 授权也已撤销”。
