## 2. R55：People 九条逐项机械化

固定上游的九条用例不是九个同义标题，各自约束不同的失效面：

1. 真库 10 人 fixture 请求 `limit=3`，只返回 3 行且给非空 next cursor；
2. `limit=2` 逐 cursor 走到 `None`，固定 10 人恰好各出现一次；
3. `limit=1` 走完全表，最新登录者第一、从未登录者精确最后；
4. 先证明目标不在未过滤前两行，再分别以 name 与 email 搜索，均只返回该目标；
5. 搜索 `_ Percent` 只命中字面下划线，不把它当 SQL wildcard；
6. 真 HTTP `limit=100000` 经 application 后，typed PostgreSQL port 实收 200；
7. nonsense cursor 的 people 与 next cursor 逐字段等于无 cursor 首页，并以非空首页作正向对照；
8. point lookup 的生产 SQL 只有一个参数化 `WHERE u.id=$1`，谓词在 `GROUP BY` 前且不含 list CTE；真库又证明 point/list 的完整 `Person` 相等；
9. missing id 返回 typed `NotFound`，role/audit 计数不变；同用例的已存在 id 正向成功。

R40 已裁决 role/access 不能照抄上游“route 先 `find`、再分步写”的竞态边界。因此第 8/9 条保留
point lookup 的复杂度、投影与不存在语义，但通过原子 `PeopleAdministration` port 行使，不重新引入
TOCTOU。对应 ledger 明确写成 `rename: ported`，没有把机制替代冒充逐行照译。

复核还发现搜索归一使用了 Rust `str::trim()`。本批改为 R51 唯一的
`openbot_domain::text::trim_ecmascript`，并以 U+FEFF 必须裁掉、U+0085 必须保留的双向样本证明没有
把两个语言的空白集合再次混写。

## 3. 缺 user 的 session：生产结构不可达

固定上游 `auth/roles.ts` 的 fake 可以返回“session 指向的 user 查不到”；但同一固定上游
`db/schema/core.ts::sessions` 与 Rust fixture 都把 `sessions.user_id` 外键绑定到 `users.id`，并规定
`ON DELETE CASCADE`。所以本批没有为了对齐 fake 而新增一个永远到不了的 domain 分支，而是对生产结构做
三段真库证明：

- 插入 orphan session 实得 SQLSTATE 23503，表内仍为 0；
- 先插 user 的正向 session 实得 1；
- 删除该 user 后 cascade，session 精确回到 0。

该条在 ledger 中标为 `rename: ported`：安全不变量保留，承载机制从 fake 的防御性 no-op 收敛到两边
生产 schema 已共有的关系约束。
