## 实现与边界

新增 `openbot_infra::net::scope_gateway`：独立 loopback listener、256-bit 每实例凭据、不可变 host/port
策略、连接/头/字节/速率/idle/lifetime 上限，以及 HTTP、CONNECT、WebSocket 转发和完整任务清理。
新 T-FIX-0057 只记录这个库的本机证据，不关闭 Browser、ComputerManager、G5/G7 或受控 Alpha。

实例由 Rust 唯一 owner 持有，bootstrap 只能显式取得 `GatewayBinding`。随机材料和自有编码缓冲使用
zeroizing owner，Debug 不包含口令；仅 private keyed HMAC digest 用于恒时验证。HTTP 请求不能改变
gateway 的 actor、policy、resolver 或实例归属；此处也没有从请求建立 `AuthContext` 的路径。
但实际 `ComputerSecurityScope`/generation、tenant policy 与 audit-before-action 的生产装配尚未接入，
不能把“独立实例凭据”升级成“业务租户隔离已证明”。

请求经过认证与 host/port/形状检查后，才调用唯一 `SafeDialer::connect_proxy_hop`。private `ProxyHop`
只能来自 fresh DNS/IP 校验和实际 peer 绑定；HTTP handshake、TCP connect、DNS/TLS 仍留在 `safe_http`。
resolver 给出的 port 被目标 port 覆盖，下一请求重新解析。host 规则使用 canonical exact/显式 subdomain
wildcard，deny 优先；`Some([])`拒绝所有 host，标准 web port 规则也不替代独立的 IP/CIDR 策略。

普通 HTTP 使用 absolute-form 输入与 origin-form 上游请求，验证 Host 一致，移除代理凭据和 hop-by-hop
头，重新构造 Host；保留 origin Authorization/Cookie、多条 Set-Cookie 和原始 path/query 编码。
无跨请求 pool、自动重试、自动重定向；一个 HTTP 请求拥有一个连接，响应后关闭。Web 客户端跟随 Location
发出的下一跳必须重新过策略。body streaming 有界，超限不继续转发；发送过前缀后失败不保证远端未执行。

CONNECT 必须是显式 host:port，无请求 body 或自由 upgrade；200 不带 Content-Length/Transfer-Encoding。
WebSocket 只接收合法 websocket upgrade 形状，101后双向传递帧。两者都受同一实例的 byte/rate/idle/lifetime
预算和撤销控制。HTTP上游 driver 被连接owner持有，显式shutdown先取消请求，再abort并join所有driver和
连接任务；Drop只发撤销并abort owned tasks，不宣称同步完成内核资源回收。

这些转发规则依据 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.6)、
[RFC 9112](https://www.rfc-editor.org/rfc/rfc9112.html#section-3.2) 与
[RFC 6455](https://www.rfc-editor.org/rfc/rfc6455.html)；HTTP parser 使用现有 pinned Hyper 1.11.0。
未复制其它项目的代理实现，未引入 npm 或新 Cargo package。

## 新增默认预算

以下是本项目新增的库级上界，调用方只能收紧；不冒充固定上游已有数值，不替代完整 Computer CPU/RSS/pids/disk。

| 维度 | 默认 / 上界 |
|---|---:|
| 所有下游连接（含未认证） | 32 |
| 下游 header、DNS/connect、upgrade deadline | 10秒 |
| 无传输进展 idle | 30秒 |
| 单连接 absolute lifetime | 30分钟 |
| 解析头 | 32KiB / 64字段 |
| 普通 HTTP request body | 8MiB |
| 普通 HTTP response body | 64MiB |
| 一个透明 tunnel 双向合计 | 1GiB |
| 实例合计转发 admission rate / burst | 8MiB/s / 1MiB |
| 单次 copy / body 切块 | 16KiB |

rate 以整数纳秒 credit 累计，所有连接和方向共享；解析后的头也计 admission cost。原始未认证 ingress
另由 parser buffer、连接数及deadline限制；不是 kernel ingress shaper。`forwarded_bytes` 是已准许转发的
payload数量，不是对端收到/执行的收据。HTTPS/tunnel采用不透明字节预算，不套用HTTP明文body配额。

## 本轮发现与修复

1. IPv6 新测试先实际失败：`Url::host_str()`保留方括号，旧 SafeDialer 把 `[::1]`误当DNS名字。
   改为匹配 typed URL Host 的 IPv4/IPv6/Domain；数值地址直接执行同一 IP/peer 校验，TLS ServerName也按
   typed host构造。修复后真实IPv6 loopback传输成功且resolver调用0。未声称验证了所有IP-SAN证书组合。
2. 初稿普通 HTTP 仍是占位，已补完整 streaming/headers/WS upgrade 路径。取消的订阅使用当前状态判断，
   避免owner先撤销、任务后订阅而错过通知；lifetime失败也必须走driver join，不能提前`?`返回。
3. 唯一出网guard首轮发现历史 R188/R189 Screen测试客户端未进清单。亲读确认唯一connect在末尾
   `#[cfg(test)] mod tests`内；清单补这一项，并以真正test module而非前面的fixture常量cfg定位边界。
   五个已知test-only客户端继续各恰一处，production网络调用面没有扩出safe_http。
4. gateway私有hop调用面单独锁定为safe_http和scope_gateway；禁止开启Hyper tracing，以免底层URI/头
   tracing扩大secret日志面。转发header另外标sensitive，自有代码不记录target、正文、cookie或口令。

## 未完成与继续方向

- Engine仍为epoch4黑洞代理/内部诊断页；本批没有启用浏览互联网，没有真实Engine proxy认证/导航证据。
- 必须由生产ComputerManager按完整scope/generation拥有本库，装配tenant policy、权限失效hook和工具管线。
- Server namespace到gateway路由、内核无直连、QUIC/WebRTC及compromised engine负向均未由本库证明。
- CONNECT只检查目标authority/DNS/IP/port，不检查加密内层SNI/HTTP authority/path。存在这类细粒度租户
  策略时仍需额外约束与实测；不把透明tunnel当作TLS内容审查或完整tenant deny证明。
- Windows真实执行等待E同事，E的R196准备分支未包含本批；该分支已获一次push授权，本主控分支未获扩展上传授权。
- G5/G7、Alpha、v4全目标不勾；不派发Actions、不运行`cargo xtask ci`、不合并PR。继续下一步Engine接线与生产scope owner。
