## 本批结果

正式 Server 二进制为 `wrok-bot-server`，新增显式 `--local` 与 16 个 `WROK_BOT_*` 配置名。
本机模式使用 `examples/wrok-bot`：一个内置助手、一个工作空间、空 knowledge sources。
模型凭据可在工作台启动后经现有 `/admin/credentials` 写入 Vault，不再因金融示例中的 managed
Agent 缺少预置 key 而无法进入工作台。金融示例和原部署默认不变，已有部署须显式迁移。

`--local` 绑定数值 loopback。未配置 Origin 时按实际端口生成 127.0.0.1/localhost 两个 Origin，
空白值采用相同默认；显式自定义值仍由原校验器检查。现有库有 SSO、导致身份模式切换为多用户时，
本机模式拒绝启动，不能悄悄转为 0.0.0.0。默认 policy 仍未配置/deny，不写入隐式 allow。

## 运行入口

这是源码构建入口，仍需已有的 PostgreSQL 17、固定 Rust 工具链和已构建 GUI；不是独立安装包。
从仓库根目录运行，或显式设置 `WROK_BOT_TENANT_PACKAGE_DIR` 到五份 YAML 所在目录。

```sh
CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 cargo build -p openbot-server --bin wrok-bot-server --locked --offline
./target/debug/wrok-bot-server --help
```

配置 `WROK_BOT_DATABASE_URL` 为专用本机数据库、`WROK_BOT_KEY_ENCRYPTION_KEY` 为持久保存的
canonical base64 AES 主密钥、`WROK_BOT_APP_DIST_DIR` 为 GUI dist 绝对路径，再运行：

```sh
./target/debug/wrok-bot-server --local
```

默认端口 3001；通过 `WROK_BOT_PORT` 修改。主密钥不能每次启动随机更换，否则无法解密已有 Vault。
工作台凭据页创建 `kind=model`、`provider=openai`、`keyId=openai-api-key` 的模型凭据。
默认 model 沿用已实现 package contract 的 `gpt-4.1`，可在所选包的 `model.yaml` 配置实际模型。
厂商变量 `OPENAI_BASE_URL` 等继续沿用；HTTP/私网 provider 必须分别显式设置 scheme 与精确 CIDR。

## 配置兼容边界

| 新名称前缀 WROK_BOT_ 后缀 | 兼容解析器字段 |
|---|---|
| APP_DIST_DIR / DATABASE_URL / DEPLOYMENT_ID / KEY_ENCRYPTION_KEY / PORT / TENANT_PACKAGE_DIR / TRUSTED_ORIGINS | 同后缀原名 |
| APP_URL / ENV / PROVIDER_ALLOW_HTTP / PROVIDER_EGRESS_ALLOW_CIDRS / PROVIDER_MAX_OUTPUT_TOKENS / PUBLIC_URL / RUN_DEADLINE_MS / SESSION_SECRET / SINGLE_USER | OPENBOT_ 加同后缀 |

解析器接受唯一快照，按上表移动 String 所有权；新旧同名配置同时出现即报 `wrok_bot_env_collision`，
未知 WROK_BOT 配置报 `wrok_bot_env_unknown`，错误不含值。退役的 Intelligence/shared token 仍被原闸门拒绝。
该兼容层是整体更名的第一步；crate/path、Desktop/Engine identity、协议及 durable identifiers 的迁移尚待后续批次，
不能通过全仓替换破坏数据、密码学派生或前端正在使用的契约。对外产品名固定使用用户原文 **Wrok Bot**。
