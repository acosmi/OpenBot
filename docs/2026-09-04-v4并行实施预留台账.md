### C. Personal Skills GUI 竖切

分支：`feat/2026-09-04-G6-personal-skills-ui`；基线必须是 R176
`3ff200a2d6f12ebdc1c7e8b6f6b26a8eae4666ea`，不得从 R172 外部分支派生。

目标只包括 v4 `/skills` 与 GUI v2 §6.2 的四个组件：

- `T-ROUTE-0011`；
- `T-UI-0067` `edit-skill`；
- `T-UI-0068` `new-skill`；
- `T-UI-0069` `skill-agents`；
- `T-UI-0070` `skill-fields`。

允许修改：`crates/openbot-ui/src/features/skills/**`、UI 的 `features/mod.rs`、`api.rs`、`app.rs`、
`shell/app_sidebar.rs`、`locales/en.json`、`locales/zh-CN.json`，以及仅为真实浏览器 fixture 所需的
`crates/openbot-server/src/bin/openbot-ui-fixture.rs`。不得改 contracts/application/infra/Server 产品
HTTP；Batch100 已提供 `GET /api/plugins`、skill save/delete、grant/revoke/for-Agent typed 后端。

闭合语义：

1. `/skills` 只把当前 actor 自己的 personal skills 列为可管理，把 deployment skills 列为只读；
   admin 在该个人页面也不得把其他 actor 的 personal skill 画进 DOM。
2. `?new=true` / `?edit=<slug>` 由 URL 持有 DetailPanel 状态，创建优先于编辑；query/slug 必须有界，
   hard reload 可恢复，missing/not-owned 不构造空编辑表单。
3. create/edit 共用四字段组件；create 永远发送 `global=false`，edit 锁住作为 key 的 slug；title/
   summary/instructions 与 Rust 后端的 256 B/4 KiB/64 KiB、control/NUL/empty 规则一致，但 Server
   仍是最终 authority。instructions 不进日志、localStorage、URL 或 error text。
4. delete 只对 personal row 提供；deployment row 无 edit/delete/grant affordance。成功写入后接受
   authority receipt 并 refetch，失败保留可重试 UI；stale/unmounted response 不得改新页面状态。
5. `skill-agents` 只列 actor owned Agents；grant/revoke 只发 closed `kind=skill/ref/agentId`，不自报
   actor/role。选中态遵守 GUI 真源“文字/图标/对勾”，不得照搬上游实心彩色按钮。
6. AppSidebar 增加真实 `/skills` destination，但不得宣称 AppSidebar 总项、slash-command Composer、
   `/admin/skills`、Plugins UI、formal golden 或 G6 完成。

验收至少包括 Rust/WASM 单测与 release Chromium journey：loading/empty、personal/deployment 分区、
create→reload、edit slug locked、只对 own Agent grant/revoke、other actor/Agent 不进 DOM、delete、
deployment 只读、双 query precedence、missing edit、失败重试、键盘焦点/命名、en/zh-CN、1280×800 与
600×900 overflow/duplicate-id/console error 均为零。若没有真实浏览器证据，不得把上述五个 T-ID 改
done。外部分支仍不得修改 parity/v4/CLAUDE/README/移交指南，由主控审计后统一落账。
