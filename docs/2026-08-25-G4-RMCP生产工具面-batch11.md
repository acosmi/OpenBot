## 2. 协议与出网边界

- Cargo 精确钉 rmcp 3.1.4；crates.io VCS 信息绑定
  4a738b9dd99eaca418b614afa433a0cbdaf8d056。
- production feature 只有 client + transport-streamable-http-client；server feature只在两份
  loopback integration test 的 dev graph。
- reqwest、stdio、child process、resources、prompts、tasks、elicitation 均不进入 production
  capability 或调用面。
- RMCP 的 HTTP backend 由 SafeRmcpHttpClient 适配既有唯一 SafeDialer：每跳 DNS/IP/peer/TLS
  复核、跨 origin credential/protocol header 剥离、总大小与真实 body read-gap watchdog 保持一致。
- 每次 list/call 都创建 client、initialize、使用、bounded close；没有跨 Bot/actor pooling。
- list 为 15 秒，call 为 60 秒 absolute cap。call 使用 RMCP RequestHandle，带 progress token；
  timeout 会发 notifications/cancelled。请求可能已发送但没有可信结果时只返回 CommitUnknown，
  application 进入 reconciliation，绝不自动重放非幂等 effect。
- live tools/list 在同一 session 内再次比对 reviewed schema hash，name 仍在但 schema 已变时在
  tools/call 之前拒绝。

## 3. Catalog 与 grant

native 0017 是 expand-only：

- runs.next_tool_call_seq；
- mcp_servers 的 catalog_generation / catalog_hash / catalog_transport_fingerprint；
- mcp_tools 的 schema_hash / effect / catalog_generation / first_seen_at / last_seen_at / available；
- plugin_grants 的 state / catalog_generation / schema_hash / effect / transport_fingerprint。

transport fingerprint 绑定 endpoint URL、vendor、provenance 与协议版本。任一工具消失、schema/effect
变化或 transport/provenance 改变，active grant 都在同一 PostgreSQL transaction 改为
suspended_missing，并追加 mcp.tool_suspended_missing；工具重新出现仍不自动启用。URL/provenance
在 refresh 前被改时，read path 会立即因 fingerprint 不一致 fail-closed，不能使用旧 grant 指向新
endpoint。

legacy NULL 保持 NULL，第一次真实 listing 才形成 complete projection。fixture
schema-0017.json 由 guarded PG17 test 机械生成：41 表 / 366 列 / 268 NOT NULL / 197 约束 /
80 索引 / 4 触发器；SHA-256
c2e85542c72a623ad7b0b3f8dc165317dfbcb91119b19a7d836ac7b711607000。

production 启动会在新增 30 秒总预算内刷新未绑定 credential 的已配置 server；单个坏 connector
只写 stable last_error，不阻止其它 Bot。credential-backed server 当前构造性不进入 granted tool
查询，不能在 OAuth/bearer exchange 尚未接线时偷用空 Authorization。

## 4. Schema、policy、content 与 audit

- 单 server：1000 tools、description 4 KiB、input schema 256 KiB、result 20000 Unicode scalar。
- vendor input schema 用 jsonschema 0.51.0；默认 HTTP/file resolver features 关闭，不允许 schema
  编译触发第二出网；pattern 固定线性 regex engine 和 1 MiB compile/DFA size limit。
- schema compile/validation 进入 bounded blocking pool；validator cache 上限 4096，达到上限整表清空，
  不允许跨 generation 无限增长。
- metadata/effect 只取 Rust-owned reviewed catalog；MCP annotations、名称、描述均不能自报 effect。
- read 工具无需 human approval；write/execute/network/credential 当前要求 every-call approval。真实
  approval store/UI 未接，因此明确写 approval_denied refusal，绝不把缺 UI 当自动批准。
- MCP arguments 在出网前拦 known secret field、known token/private-key/JWT/canary 形状；
  content_secret_blocked 走同一 durable refusal audit，不保存 secret 或其可验证 hash。
- vendor result进入模型前标记为 Untrusted MCP content，并带 server/tool provenance；vendor isError
  与本部署 policy refusal 保持不同文案与 stable code。
- tool audit payload 新增只取权威 decision.bot 的 allowlisted bot 字段；callback body、模型与
  vendor 均没有自报 Bot 的参数位。

## 5. Context、callback 与 sequence

PostgresAgentContextSource 每 run 从当前 grant 读取 vendor 原 description/schema，并追加基于 validated
server/tool id 的 connector guidance。remote AG-UI 的 RunAgentInput tools 与 assertion whole-tool-set
digest 来自同一查询结果。

PostgresRemoteCallbackAuthenticator 在 token/assertion/run/lease/role transaction 内用同一 catalog
重读 current tool set；随后 RemoteAgentToolInvoker 把 authorization 交给同一个
AuthorizedAgentToolGateway 与 ApplicationService，不存在 callback 专用 executor。

PostgresAgentToolSequence 以 runs.next_tool_call_seq 单条 UPDATE 原子分配。真实 PG 测试让两个独立
allocator 同时请求，实得连续且不重复的 5/6，重建第三个 allocator 后实得 7；跨 replica / restart
不再回到 0。
