## 2. R60 裁决

### 2.1 Theme

GUI 第一真源规定 `crates/openbot-ui/design/tokens.toml` 是 light/dark/system 的唯一来源，故不
实现上游 `validateThemeCss`：

- package 输入类型与 loader 文件表都恰为 brand/agents/channels/model/knowledge；
- `theme.css` 即使存在也不打开；
- 历史 `skin.stylesheet` 只产生兼容状态，不读取或执行文件；
- 两条上游 theme 测试改记 `remove: not-applicable-with-proof`，没有用“写一个恒拒绝 CSS 的假
  validator”冒充移植。

### 2.2 Group/membership

- `allowed_groups=[]` 与空组名在纯 parser 阶段拒绝；
- 多用户具名组必须至少有一个动态 IdP mapping；缺 mapping 的 provider 清单稳定排序；
- 单用户 principal 进入全部包 channel，报告 `single_user_groups_ignored`；
- `all` 对全部有效用户全量 provision；运行时可见性仍只查 materialized membership；
- audience 收紧删除 membership 时，同事务推进 auth generation 并清 session；
- 0015 没有保存 group normalization provenance，故包同步对已存 `users.groups` 只做逐字匹配，
  宁可暂时少授予；下一次 verified 登录用权威 provider mapping 补齐，不跨 IdP 扩大等价类。

### 2.3 Environment、品牌与所有权

- parser 从不读进程环境；Server 只投影 `MANAGED_AGENT_AG_UI_URL`，不会把 session/KEK/token
  等 secret 暴露给 package；
- loader 单文件上限 1 MiB，错误不回显 YAML、环境值或本机路径；
- 随包示例改为 `fintech / Ledgerline`，并反向拒绝第一真源禁止的对外标记；
- PostgreSQL 同步通过 application-owned port，锁定 package 表并拒绝 user/cross-package
  Agent/Profile/Channel 覆盖；所有写在一个事务；
- 未设 `DEPLOYMENT_ID` 时使用已解析校验的 package tenant id，不从目录路径铸造 identity。
