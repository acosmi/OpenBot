## 2. Policy：记录、缓存和传播只有一份答案

固定边界如下：

- `action_policy(id='current')` 是跨重启记录；显式配置只是无行时的 fallback；二者都不存在时是
  独立 `Unconfigured`，继续 default-deny，不复活上游隐式 `allow:["true"]`；
- 每个 replica 的内存快照同时持有 raw policy 与 `Arc<CompiledActionPolicy>`；load/set/reset/refresh
  时编译一次，acting 热路径连续读取只 clone 同一 Arc；
- 本进程 operation lock 串行 refresh 与 set/reset，防止旧 refresh 在新 commit 后覆盖缓存；
- upsert/reset 与空 payload `pg_notify('action_policy_changed','')` 同一事务，rollback 不发通知；
- listener 使用连接池之外的专用 tokio-postgres 连接；首次 LISTEN 与每次断线重连成功后先整表重读，
  覆盖离线期间漏掉的通知。payload 从不承载规则，避开 8000-byte 上限与截断真源；
- Server main 在监听 HTTP 前 load，并把 listener 持有到 graceful shutdown。

PG17 的 13 条逐项证明 restart、显式 config fallback、reset 删除行、两次 set 单行最新值、updated_by、
纯内存模式、跨 replica set/reset/mode、无 DB refresh、订阅恢复 catch-up、rollback 不通知，以及无人接收
NOTIFY 时已提交行仍可被新进程恢复。
