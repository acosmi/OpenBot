# Rust 工具链 `1.94.1` → `1.98.0` delta 审计

> **形态**：delta audit（v3 §1.2 末段要求：升级任一固定来源必须新建，记录旧/新版本、协议差异、许可证差异、迁移影响和回归结果）。
> **日期**：2026-08-22（America/Los_Angeles）。**裁决人**：仓库所有者，2026-08-22 明文选择「升到 1.98.0」。
> **影响面**：v3 §1.2 固定基线表、`CLAUDE.md` §3、`rust-toolchain.toml`、`Cargo.toml` 的 `rust-version`，以及连带的 `oxc` 全家桶版本。
> **修订登记**：v3 §28.1 第 R21 行。

## 1. 为什么升（旧 pin 站不住的三条实据）

| # | 事实 | 复算命令 |
| --- | --- | --- |
| 1 | 旧 pin `1.94.1` 发布于 **2026-03-25**，本轮升级时已是 5 个月、4 个 minor 之前的版本 | `rustc --version` |
| 2 | `1.98.0` 发布于 **2026-08-18**，即 v3 定稿（2026-08-21）**之前三天**。v3 §1.2 写下 `1.94.1` 时新版已存在，而正文没有为这个选择写过任何理由——它是从 CrabCode 基础设施继承的默认值，不是对本项目做过的权衡 | `rustup check` |
| 3 | **旧 pin 正在卡工具，不只是"旧"**：v3 §24 G0 / G8 点名要 AST 级 test inventory，实现用 `oxc_parser`；`cargo build` 在 1.94.1 上直接拒绝 `oxc_parser@0.146.0 requires rustc 1.95.0`，Phase 0 被迫退到 MSRV 台阶上的 `0.139.0` | 见本文件 §5.2 |

反方唯一站得住的理由是「1.98.0 发布仅 4 天，Rust 的 `.1` 修订版常在数周内跟上」。裁决接受该风险，理由：本仓此刻零业务代码，换工具链的迁移成本处于全生命周期最低点；且 v3 §1.2 的 delta audit 义务无论何时升都要履行一次，推迟只会让它落在代码更多的时候。

## 3. 协议 / 语言面差异

- **edition 不变**（仍 2024），无语言版次迁移。
- 本仓此刻只有 Phase 0 的骨架与 xtask，不含任何跨进程协议实现，因此**无 wire protocol / ABI 差异面**。将来引入 Tauri / Leptos / Electron shim 后，跨版本 ABI 只在同一 release epoch 内自洽（v3 §16.2），不受本次升级影响。
- 实际差异集中在**工具链自带 lint 集**，见 §5.1。

## 4. 许可证差异

Rust 工具链两版均为 Rust 项目的 `MIT OR Apache-2.0` 双许可，本次升级不引入新的许可证义务。

> **未验证项（诚实标注）**：本机两个工具链均以 `rustup ... --profile minimal` 安装，目录内**不随带** `LICENSE-MIT` / `LICENSE-APACHE` 文件，因此无法在本地对两版许可证文本做逐字节比对。上句结论来自 Rust 项目的公开许可政策，不是本轮实测。解除条件 = 以 `--profile default` 重装任一版本后比对，或在 CI 里对发行物的 NOTICE 生成步骤中校验。

## 5. 迁移影响

### 5.1 新增 clippy lint 命中 1 处（唯一的代码改动）

`1.98.0` 的 clippy 新增 / 收紧了 `clippy::collapsible_match`，在 `crates/openbot-testkit/src/bin/xtask.rs` 的 `schema_version` 校验处命中；`1.94.1` 的 clippy 不报此项。

- 修法：把 `Some(v) => { if cond { … } }` 改写为 match guard `Some(v) if cond => { … }`，语义等价，不放宽任何判据。
- 该处在改动前后都对 `schema_version != 1` 判红，`parity-check` 的行为未变（见 §6 回归）。

### 5.2 连带升级 `oxc` 全家桶 `0.139.0` → `0.146.0`

旧 pin 下 `0.139.0` 是唯一可编版本（oxc 的 MSRV 台阶：`0.139.0 → 1.94.0`、`0.140.0 → 1.95.0`）。`1.98.0` 解除该约束后升到实测最新的 `0.146.0`，涉及 `oxc_allocator` / `oxc_ast` / `oxc_ast_visit` / `oxc_parser` / `oxc_span` 五个 crate（oxc 全家桶同步发版）。

**行为差异实测为零**：两个版本各跑一次 `xtask test-inventory`，产物 `fixtures/tests/upstream-ast-inventory.json` 在剔除 `parser` 版本记录字段后**逐字节相同**——`1,047` 个 `test` 节点、`229` 个 `describe` 节点、`105` 个文件的三档分布（`ported 101` / `covered-by-golden 3` / `not-applicable-with-proof 1`）全部一致。

`test_inventory.rs::OXC_VERSION` 常量与 `[workspace.dependencies]` 之间有单测 `oxc_version_matches_workspace_manifest` 做漂移守卫；本次升级时该守卫**确实判红并拦住了只改一半的改动**，同步常量后转绿。

### 5.3 供应链闸门被真触发：`deny.toml` 的 build script 白名单需扩 4 条

oxc 升级把 4 个新 crate 带进依赖图，且它们都带 `build.rs`：`dragonbox_ecma 0.1.12` / `num-traits 0.2.19` / `owo-colors 4.3.0` / `rustversion 1.0.23`。`cargo deny check` 的 `bans` 段当场判红 `build-script-not-allowed`。

**这是闸门按设计工作，不是回归**：v3 §16.3 要求"build.rs、proc macro、FFI 和 `unsafe` crate 单列审计"，fail-closed 白名单的作用正是逼人去读新出现的构建期代码。四份本轮逐字读过，全是编译期能力探测（`rustc --version` → `cargo:rustc-cfg=…`；`num-traits` 经 `autocfg` 试编表达式；`rustversion` 另向 `OUT_DIR` 写生成源码），**无网络请求、无下载、不执行第三方二进制**，据此加入白名单并在 `deny.toml` 就地记下体检结论。

> 单独记一笔：`rustversion` 的构建脚本不在顶层，`Cargo.toml` 声明 `build = "build/build.rs"`；只 `cat build.rs` 会得到"文件不存在"而误以为它没有构建脚本。

### 5.4 未产生影响的面

- `Cargo.lock` 除 oxc 五个 crate 及其上述 4 个新传递依赖外无版本变化。
- `deny.toml` 的 advisories / licenses / sources 三段结论不变（只有 `bans` 段需扩，见 §5.3）。
- 9 份 parity ledger 的内容与 `parity-check` 判定不变（升级当时 1,641 条 entry、0 违反；条目数此后随 G1 增长，不变的是「0 违反」这条判定）。
- 设计资产（Inter / Lucide）、`tools/pins.toml`、`provenance/sources.spdx.json` 与工具链无关，零改动。

## 6. 回归结果（本轮在 `1.98.0` 上实跑）

```text
rustc --version                                                    → 1.98.0 (88d9e12ae 2026-08-18)
cargo fmt --all -- --check                                         → PASS
cargo build --workspace --all-features                             → PASS
cargo clippy --workspace --all-targets --all-features -- -D warnings → PASS（修 §5.1 之后）
cargo test --locked --workspace --all-features                     → PASS
cargo xtask ci                                                     → PASS（4/4）
cargo xtask parity-check                                           → 0 违反（条目数不在本文件钉死：它随台账增长，
                                                                     #   真源是各台账自己的 recount，由 cargo xtask recount 逐条实跑）
```

对照基线：同一套闸门在升级前的 `1.94.1` 上也全绿，因此**红转绿的差集恰好等于 §5.1 那一处**，不存在被升级掩盖的既有问题。

## 7. 复算命令

```bash
# 版本事实
rustup check                                                     # 1.94.1 -> 1.98.0 (88d9e12ae 2026-08-18)
rustc --version                                                  # rustc 1.98.0 (88d9e12ae 2026-08-18)
grep -c 'channel = "1.98.0"' rust-toolchain.toml                 # 1
grep -c 'rust-version = "1.98.0"' Cargo.toml                     # 1

# 两处 pin 同值（漂了就红）。刻意不用 `grep -oP`：PCRE 在部分 locale 下直接报
# `-P supports only unibyte and UTF-8 locales`，两侧同时取到空串会让 `test "" = ""`
# 假绿——空值必须先判死（负向对照：把 a/b 置空应打印 DIFFER）。
a=$(sed -n 's/^channel = "\(.*\)"/\1/p' rust-toolchain.toml)
b=$(sed -n 's/^rust-version = "\(.*\)"/\1/p' Cargo.toml)
[ -n "$a" ] && [ -n "$b" ] && [ "$a" = "$b" ] && echo "SAME ($a)" || echo "DIFFER a=[$a] b=[$b]"

# oxc 五个 crate 同版本，且与代码常量一致
grep -cE '^oxc_(allocator|ast|ast_visit|parser|span) = "0\.146\.0"$' Cargo.toml   # 5
grep -c 'const OXC_VERSION: &str = "0.146.0";' crates/openbot-testkit/src/xtask/test_inventory.rs   # 1

# AST inventory 未因换 parser 而改变
jq '[.nodes[] | select(.kind == "test")]     | length' fixtures/tests/upstream-ast-inventory.json   # 1047
jq '[.nodes[] | select(.kind == "describe")] | length' fixtures/tests/upstream-ast-inventory.json   # 229
jq -r '.parser.version' fixtures/tests/upstream-ast-inventory.json                                  # 0.146.0

# 闸门
cargo xtask ci
cargo xtask parity-check
```

对不上 = 工具链或依赖漂了 → 先核 `rustc --version`，再按 v3 §1.2 新建下一份 delta audit。

## 8. 遗留

1. §4 的许可证逐字节比对未做（`--profile minimal` 不随带 LICENSE 文件），解除条件见该节。
2. `1.98.1` 若在近期发布并修复回归，按 v3 §1.2 走一次**新的** delta audit 决定是否跟进；不得静默升。
3. 本次升级只在 Windows x64 (msvc) 上实跑过。三平台 CI（v3 §16.3）尚未在任何 runner 上执行过——本仓 GitHub Actions 目前仅 `workflow_dispatch`，见 `.github/workflows/ci.yml` 的说明。macOS / Linux 上的 `1.98.0` 行为本轮**未验证**。
