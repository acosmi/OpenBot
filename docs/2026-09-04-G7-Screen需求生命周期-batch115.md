# Batch115：Screen需求驱动暂停与恢复

日期：2026-09-04。分支：`feat/2026-09-04-G7-screen-demand-lifecycle`。
依据：v4 §12.4–§12.6、§24 G7、§28.1 R190。实现提交：`f7947e4`。

## 结果与边界

最后viewer离开后，Rust owner现在会停止采集并保留原页面；重新连接恢复同一renderer和document。
这补齐了此前只关socket、仍由测试显式停止Engine的缺口。真实Server TCP WebSocket的idle关闭也已
接入同一owner验证。production ComputerManager/source装配、生产auth失效hook、Desktop loopback、
fps/paint/fallback与Windows/runsc runtime仍缺，不关闭完整T-BROP-0027或G7。

## 实现

- protocol/release epoch显式升4，descriptor/generated module/hash/bundle verifier同值。
  新增closed `screencast {enabled}`和exact `screencast_state` ACK；无自由CDP或URL。
- pause只停Page采集、移除frame listener、等待frame与ACK drain并校counter；resume重新订阅并启动采集。
  window、document、输入内容、scroll、ingress decoder与单调sequence保留；重复pause/resume返回replay。
- 合并重复的command shape/scope校验，shim为595/600 LOC；未放宽API/文件/LOC闸门。
- ScreenHub只将已消费ticket的viewer计入需求；pending ticket不驱动持续采集。detach/撤权即时关闭需求，
  不等待旧viewer handle销毁。source发布/清理及owner收尾都比较同一registration，旧实例不能影响同key新实例。
- `ScreenEngineOwner`持有唯一EngineProcess；16项有界队列，输入与capture操作各750ms、shutdown1500ms。
  wire超时后不复用进程，避免晚到ACK污染下一命令。
- 输入队列只存非权威HumanInputTicket；执行时在当前ControlService锁内重验scope/epoch/expiry并铸receipt，
  锁持有到有界input ACK。排队中epoch变化的请求在pipe前拒绝；不把排队前receipt当执行时authority。
