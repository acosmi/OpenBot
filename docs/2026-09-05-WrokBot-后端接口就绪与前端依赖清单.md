# Wrok Bot 后端接口就绪与前端依赖清单

> 当前发布范围（R204）：**macOS首发**；Windows后续独立验收。前端实施由独立窗口负责，
> 支持态必须依据当前macOS后端真实能力；不把Windows未通过映射成macOS不可用。

日期：2026-09-05。后端负责能力、DTO/API 与真实执行；页面、交互、视觉及具体前端任务由前端窗口决定。
此清单是当前源码与本机联调状态，不承诺尚未实现的接口，不以旧夹具代替正式服务。

## 现有稳定契约

| 能力 | 当前 HTTP/typed 入口 | 就绪程度/限制 |
|---|---|---|
| 身份/偏好/费用 | `/api/me`、`/api/me/session`、GET/PUT `/api/me/preferences`、GET/PUT `/api/me/run-cost-budget` | 正式PG路径已接；单用户session不可退出，费用上限真实加载已联调 |
| Agent/频道 | `/api/agents` 与现有详情/生命周期；`/api/channels`、`/api/channels/{id}`、现有routing | 正式路径存在；本机包有wrok-assistant与wrok-workspace，用户Agent生命周期按既有权限 |
| run/历史/停止 | POST `/api/threads/mint`、POST `/api/threads/{id}/runs`、POST `/api/threads/{id}/runs/{run}/cancel`、GET conversation/events/ws | durable PG与共享typed契约；Stop 202是已接收请求，终态以SSE/snapshot为准 |
| Acting审批 | GET `/api/tool-approvals`、GET events、POST `/api/tool-approvals/{id}` | 已有durable审批；不能据此推导尚未接入的Computer工具已可执行 |
| Agent人工暂停 | GET `/api/me/remote-interrupts`、PUT `/api/me/remote-interrupts/{id}` | production已装配，本轮真实GET200/空interrupts；旧UI fixture503属于夹具缺项 |
| 组件决策 | GET `/api/components/human-decisions`、POST `/api/components/human-decisions/{id}/answer` | 与acting approval分离，沿用shared contracts |
| Skills/MCP管理 | GET `/api/plugins`；POST `/api/plugins/skills`；DELETE `/api/plugins/skills/{slug}`；POST/DELETE `/api/plugins/grants`；GET `/api/plugins/for/{agent}` | 正式backend已实现个人/部署技能、owner/admin权限和grant；**没有独立GET /api/plugins/skills**，列表取plugins页面DTO |
| MCP连接/OAuth | `/api/plugins/servers`、custom、refresh、oauth-client、connect；GET connections及DELETE disconnect；oauth/callback | Server正式路径已实现；需要实际vendor配置。Desktop Local installed-app OAuth仍缺，不能复用Server回调冒充 |
| 凭据 | GET/POST `/api/admin/credentials`；POST `/{id}/rotate`、`/{id}/revoke` | 真PG/Vault已联调，read DTO无明文；管理shared contract在credential_admin.rs |
| 记忆 | `/api/memories`、control、recall、`/{id}`、`/{id}/forbid` | 正式scope/显式写入/纠正/删除已接；没有隐式抽取或额外向量库 |
| 策略/人员/审计 | GET/PUT `/api/computers/policy`、admin people/role/access、audit-events | 正式路径已接；无配置policy是deny，不能由UI预选或临时兜底变成allow |

精确 body/receipt 以 `crates/openbot-contracts/src/command.rs`、`mcp.rs`、`credential_admin.rs`、
`screen.rs`、`desktop.rs` 等真实文件及注册路由为准；未列生命周期子路由不代表删除它们。

## 仍未形成完整产品入口的能力

| 能力 | 当前事实 | 下一步后端工作 |
|---|---|---|
| Browser/Computer资源管理 | 有scope、ControlService、residency owner、Engine及gateway库；公开路由只有policy和Screen transport | 接入当前auth/Agent/run、唯一manager、真实Engine source与gateway；之后发具体typed DTO，不给前端自由路径/CDP |
| Screen/Handover | POST `/api/screen/sessions`、query-free `/api/screen`双subprotocol binary WS已实现；生产manager尚无完整source | 同一scope/current generation来源和auth撤销hook、input/lease/secret受控入口；当前存在transport不等于可用画面 |
| file/shell | v4要求封闭files/list/read/write/exec；尚无完整生产typed公开入口 | 同一工具审批/审计管线、workspace/realm/sandbox、process-tree cancel；不临时增加任意shell或路径API |
| 原生OS电脑控制 | 有固定自有来源的隔离评估副本；尚未进入本产品生产执行路径 | 本产品OS权限/全局输入互斥/取消/receipt与像素出网控制，逐平台真验 |
| Desktop Local/Remote | typed unary/realtime及Local数据面/Agent/window-last builder已有；独立可安装宿主与完整Screen/Local OAuth缺失 | 宿主/identity/sidecar装配、真实Wry、安装升级与跨平台验证；Remote沿用Server API |
| 安装/备份/恢复/迁移 | `openbot-migrate`有retention preflight和Intelligence bundle导入相关CLI；没有通用HTTP备份恢复控制面 | 原子PG sidecar/新数据backup-restore/checksum/升级失败恢复；不从CLI存在推断产品备份已交付 |
| 心跳/定时产品面 | Agent内部heartbeat已有；定时任务CRUD/独立scheduler不在当前已实现API内 | 按用户后续裁决与第一真源明确新增范围，不能把内部heartbeat伪装成用户定时任务 |
| 全局能力状态 | 现有anonymous auth capabilities只含rust mode、durableHistory、authProviders、ssoConfigured | 增加真实能力投影前先同步封闭契约；不得把ssoConfigured=false解释为具备空配置的SSO管理服务 |

## 本轮联调发现

`/api/admin/identity-providers` 在本机模式为503 / dependency_unavailable。
原因是本机main没有创建DynamicSsoService，而handler始终注册；它不是前端请求格式问题。
后端将明确提供支持面投影或接线，再通知前端处理能力状态；页面和交互方案由前端负责。
不要为消除报错返回伪造空列表，不启用未经配置的企业认证。

正式Server+独立PG在39026完成只读GUI与后端测试后已正常关闭。前端39025是独立UI夹具；
本机模型端为模拟器，任何这组截图/回包都不作为真实vendor调用证据。

## 变更协作

近期已落 `wrok-bot-server --local` 与 `WROK_BOT_*` 配置别名；crate/lib名称、现有API/body、
Tauri command、Screen协议本轮均未因品牌改名而变化。整体命名迁移仍由后端分批完成，每次破坏性
wire或宿主变更先给前端准确字段/版本与联调入口。前端不得据此提前创造已经成功的操作结果。

E2 Windows分支 `fix/2026-09-05-windows-e-delivery-audit` 已交用户转同事；3项真实Engine失败待修。
原外派GUI G/H和其在制审查材料由前端窗口统筹评估；后端只协助共享DTO/权限/接口问题，
不把未验收候选混入当前GUI工作树。


## 显式技能调用追加契约（R203）

BeginThreadRunBody/BeginThreadRun及用户ThreadHistoryMessage新增可选 `selectedSkillSlugs`，
空数组省略；最多16个有序唯一slug，每个沿用2–40字节语法。message必须非空。Rust解析当前授权
并在同事务保存独立system指令快照、用户原文和选择；renderer不提交instruction正文。
新run缺失/撤销选择统一404且不创建，重复/语法/超量400；同runId改变message或选择/顺序409。
unknown仍使用原runId与原有序选择重试。原历史保留，回读选择不依赖当前grant。
详情与实测界限见 `docs/2026-09-05-WrokBot-显式技能执行与持久快照-后端验收.md`。
