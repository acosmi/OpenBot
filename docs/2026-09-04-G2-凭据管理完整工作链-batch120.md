## 实现与第一性原理裁决

固定上游 `credentialInput` 明确只允许手工创建 `model / connector / mcp`，不能把六种库存类型
都开放给管理员创建。Rust 保留这个 allowlist；Agent、OAuth client、个人 token 仍由各自权威流程产生。
状态列表可以显示六种类型，但没有任何读取现有明文或密文的字段。

新增共享 CredentialAdministration 与四条 typed command，接入 Server/Desktop 同一个 PostgreSQL
ApplicationService 组装。HTTP 的 fresh-admin/Origin parts guard 在 body poll 前执行；Desktop 使用
宿主 window 身份、新鲜度和 admin gate。数据库再以配置 deployment/tenant、当前 user generation、
角色及 revoked_access 复核，并持有用户共享锁。cursor 只决定读取位置，不能携带权限。

创建/轮换每记录产生新 UUID、随机 DEK 与 v2 AAD 信封，存后解封回读比较，再同事务写 typed
hash-chain audit。轮换锁住前驱，kind/provider 不变；keyId/公开 metadata 可以明确更新，改变模型引用
后配置仍需同步。新记录、MCP 引用、credential generation、grant suspension、旧记录退役和 audit
作为一个事务提交。回读、SQL 或 audit 失败时新凭据不生效；并发轮换同一前驱只有一个成功。

“active pointer 原子切换”对 MCP 是物理 credential_id，对 model 是同事务中旧 active 行退役与新行
成为候选；没有另建第二套模型选择算法。固定上游的 newest-active + created_at/id tie-break、
stored-first/environment fallback/corrupt-no-fallback 仍保持。撤销一条凭据不等于停用其它独立 active
记录或环境配置，GUI 的确认文案明确这一点。

MCP 撤销保留指向已撤销凭据的不可用指针，不能设置 NULL 后变成匿名访问。其 grants 同事务失效。
个人 OAuth token 或当前 deployment client 退役时，join 清理、本地 tombstone、安全审计以及原始
client/resource/transport/CIDR 快照同事务落地。已有 reconciler 使用该原快照，绝不换成后来同名服务
的新 client；后续 server remove 也保留已冻结的 pending 上下文。永久损坏只 claim 一次后转
operator_required，不能无限重试或向错误目标发送 token。完成时删除已无用途的网络快照。

Model、legacy connector、Agent endpoint credential 和部署 bearer 的厂商清理由 operator 完成；
OAuth client registration 自身也需要 operator 清理。本地 200/retiredAt 不代表厂商撤销成功。
SQL/audit 提交结果未知仍为 reconciliation-required 202，GUI 不自动重放非幂等写入。
原 v4 §2.4 的“失败时新凭据不生效”在此明确指本地校验/事务失败；外部清理独立，且必须如实展示。

公开 metadata 放在 `_openbot_credential_admin.userMetadata` 中，不能覆盖 Rust 内部生命周期字段；
读取排除内部 revocation 上下文。metadata page 为 100 行 keyset，单页和单行都有边界；模型默认
provider/reference 从既有配置只读投影，GUI 可预填，不能据此声称密钥已通过厂商验证。
普通引用进入受限 audit identifier，超过 256 字节但合法的 keyId 记录摘要/长度，不放宽通用审计长度。

metadata、创建、轮换与撤销；密钥不回显，失败不回填，新鲜度不足提示重新登录。轮换锁定类型与
provider，保留明确编辑 keyId 的能力；UTC 日期有标识，提交/取消后恢复焦点。
