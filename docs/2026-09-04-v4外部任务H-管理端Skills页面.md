## 验收

1. AdminShell 与后端 current actor/admin 检查共同成立；loading/empty/error/未授权/过期/撤权明确。旧请求返回不恢复已失去权限的数据或 dialog。
2. 部署级 scope 由既有 DTO 的 global 语义表达；个人技能不可在此被误修改、删除或提升部署权限。重复 slug、不可见资源与后端稳定错误按实际语义呈现。
3. 安装/编写、编辑、删除及页面实际需要的 grant/revoke 流程有真实请求、读回和失败恢复。串行写入，unknown commit 不自动重试；离页和重复点击不产生重复 effect。
4. 技能正文按纯文本编辑/显示，不执行 HTML/JS，不把正文中的 agent/tool 名称当 authority；引导清楚说明 skill 不增加权限。
5. 对固定上游存在而当前 backend/DTO 未具备的能力（如具体安装来源或完整授权面），列出差异，不画假成功按钮。
6. UI 定向单测、Clippy、WASM check；锁定工具 offline release build，i18n/design/css/bundle/dependency gates。使用已有 Admin 页面错误与焦点模式，主题/token 不自创。
7. release 真实浏览器执行中英、两主题、键盘新增/编辑/删除/取消、焦点返回、loading/empty/error/unknown/降权，检查重复ID、可访问名称、横向溢出与 console。
8. 可运行 PG 时使用全新隔离库，证明现有 PG/Vault/Application/真实 session→GUI 写入读回、scope/admin/grant与audit；提供删库/停机清理结果。fixture 浏览器、PG后端分别通过不能冒充整体链已通过。
9. Desktop transport 可复用既有 typed路径，但未在真实 Wry/Windows 做的旅程必须单列；正式 golden/AX未做则保持未完成。

交付基线后单一候选提交和逐项证据，不自行关闭 route/G6。主控收到 Personal Skills 候选后处理共享 API/locale 的最小集成，执行方不改其它工作树。
