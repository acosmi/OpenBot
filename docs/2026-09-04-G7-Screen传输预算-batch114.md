## 2. Server 默认值（新增，不冒充上游）

| 限制 | 实际默认 |
|---|---|
| 图片字节token bucket | 8MiB/s；一次burst最多8,388,676 bytes，即contracts的8MiB图片+68-byte viewer header |
| 控制帧token bucket | burst20，随后10条/s；与图片预算独立 |
| 存活 | 10秒发Ping；只有当前8-byte递增challenge的匹配Pong可续期，且只能消费一次；30秒idle |
| 写入 | frame/Ping/Pong最多1秒；close最多100ms；失败/超时立即退出并drop viewer |
| write buffer | immediate write，阈值0；最大8,389,700 bytes，即一张最大binary frame+1KiB framing余量 |

token bucket以整数纳秒credits累计，保留不足一个byte的refill而不向上取整；超过capacity不能储存额外
额度，时间倒退拒绝，不借未来额度。图片预算包括viewer header和JPEG，不包含TCP/TLS/RFC6455外层开销；
本批不是链路总带宽测量。超过预算关闭该socket，不产生frame重试队列。

持续发帧、客户端Ping、旧Pong、无匹配Pong均不能续期。deadline在select中优先；正在进行的写入仍受1秒
上限约束，因此失活检测最坏还可能受当前一次写入与100ms close影响。静态画面正常Pong不会因不出帧被误断。
首帧发送后释放引用，避免该连接一直额外持有旧图。Tungstenite当前实现以同一payload替换其待发送Pong，
然后flush；未新增生产`futures-util`依赖。

仅Server frame transport增加这些默认值，不接收renderer提供的limits；existing hub仍以active+pending共同
限制每stream8个viewer。Desktop、production auth invalidation、global process budget、fps与capture-to-paint
仍是独立余项。
