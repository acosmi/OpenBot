## 2. R53：单用户 canonical identity 修复

固定上游 `DEV_ACTOR` 与已冻结 CEL fixture 都把单用户归属键钉为：

```text
id    = dev-local-user
email = dev@openbot.local
role  = admin
```

W-4 生产入口却自造了 `single-user` / `single-user@localhost` / `Local Owner`。固定 id 是旧
thread/memory 跨重启归属键，改名会让现有数据看起来像属于另一个人。旧 SQL 还有两项独立缺陷：

- `ON CONFLICT(id) DO NOTHING`，canonical email/name 被改坏后永远不恢复；
- 同时插 admin 与 user 两行，违反 `RoleAssignmentPlan` 已固定的“删除非目标角色 + upsert 唯一目标”。

修订后：

- `openbot_infra::auth::single_user::initialize_single_user` 是唯一 PostgreSQL provisioner；
- disabled 在 `pool.get()` 前返回，测试用不可达惰性 pool 证明连接数仍为 0；
- enabled 单事务 upsert 固定 id/email/name，已有 `auth_generation` 不回退；
- 角色写复用 `plan_set_role(Admin)`，最终只有 admin；
- canonical email 被另一 user 占用时实得 SQLSTATE 23505，整事务回滚，错误 Display/Debug 不含地址；
- Server resolver、HTTP 测试与 transport 对拍只经同一 `SINGLE_USER_ACTOR_ID`；旧 Rust 字面量清零。

## 4. R54：fresh 库二次启动阻断

为验证 R53 不是只在组件里成立，本轮启动了真实 `openbot-server`。首启、health/readiness/me/
metrics、canonical user/唯一 admin、Ctrl-C 都正常；同一 fresh 库二启却报
`legacy_data_migration_unverifiable`。根因是 Rust baseline 刻意不伪造 Drizzle 账本，而旧 main
把本应属于 fresh 的 `Unverifiable` 也当成 legacy 拒绝；baseline 与 native 又分两个事务，存在
进程死在中间的歧义窗口。

修订后：

- `db::fresh` 把 baseline、0013–0015 与 native ledger 放在同一事务；
- fresh 在任何 DDL 前取同一 migration advisory lock 并锁内重检，双 replica 实得恰好
  Fresh + RustManaged，而不是第二个撞 CREATE；
- Server 启动分为 Fresh / RustManaged / LegacyUpgraded；
- RustManaged 仍跑 schema boundary，并由 `native::apply` 校验版本、name、checksum 与空洞；
- 已有 public schema 若两种账本都没有，继续报 `legacy_data_migration_unverifiable`，不猜 0003；
- 同名异形 native ledger 让 bootstrap 失败时，public 表数实得 0，证明 baseline 同事务回滚。

修复后保留的现场库二启正常监听，Ctrl-C exit 0；命名临时库随后已删除。
