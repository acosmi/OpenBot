# Batch119：密钥输入所有权与请求清理

日期：2026-09-04；分支：`fix/2026-09-04-G6-secret-input-ownership`；起点：`13b7d87`（R194）。
依据：v4 §6.4、§17.2、§24 G2/G6 与 R195；GUI 第一真源 §6.1、§8、§9。

## 发现与修复

对现有 Alpha 工作链复核时发现：Plugins OAuth、Identity Providers OIDC、Agent Authorization 三处
使用 `RwSignal<String>` 保存密码输入；Agent 的响应式表单校验还会反复构造含认证的请求。
即使密码控件视觉遮挡、返回 DTO 不回显、关闭时清空，仍不满足 §6.4。Batch62/70/117 的局部
浏览器绿不能证明这条所有权边界。该问题在本批修复，不通过修改真源允许响应式明文来消除违规。

普通 `InputType` 删除 Password 变体，密钥输入统一为 Input 家族的 `SecretInput`：
controller 只有 DOM NodeRef、Empty/Valid/Invalid、修改代次和固定校验策略，不能保存 Rust 明文字符串。
控件没有 reactive value prop、明文 change callback、value 属性或预填接口；Field 仍拥有 label/ARIA。
输入事件只在临时 `Zeroizing<String>` 中校验；表单的响应式计算只读取非 secret 校验事实。

保存时读取并清空密码 DOM，转交零化请求；关闭、取消、OIDC/SAML 切换及卸载清理输入。
失败不会把请求中的密钥恢复到控件，重填后才可再次发送。Agent 的显式连接测试允许密码留在当前
DOM，供接着保存；测试请求副本临时零化，编辑后只靠非 secret 代次撤销旧测试结果。
编辑 Agent 时空输入仍表示保留已保存的凭据，不从服务端读取旧值。

MCP/Agent secret DTO 在校验之前建立零化所有权，Serde 字段同样先包裹零化分配，后续未知字段导致
反序列化失败也能清理该分配。OIDC outbound secret 从普通 String 改为 Zeroizing<String>。
三个 constructor 新增无明文复制的 ownership transfer；pointer/Arc-share、脱敏和 wire 回归测试通过。
敏感 GUI 请求直接序列化到临时零化 JSON，不经过 serde_json::Value；交给浏览器后，在 await 前丢弃
Rust JSON 与密钥 DTO，只为 receipt 留非 secret 的 provider/issuer/protocol 信息。

这不声称能物理擦除浏览器 DOM 引擎、JS 字符串、WASM 桥接、HTTP 栈或 OS 的全部瞬时副本。
Rust 清理范围只覆盖当前显式持有的分配；没有把“Debug 脱敏”或密码视觉遮挡当作擦除证明。
