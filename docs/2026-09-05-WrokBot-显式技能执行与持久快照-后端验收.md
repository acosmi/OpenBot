# Wrok Bot 显式技能执行与持久快照

日期：2026-09-05。依据：v4 §9.6 / §24 / §25 / §28.1 R203。范围仅后端及共享DTO；
页面、选择交互和视觉验收由前端窗口负责。

## 问题与行为

原 Rust 后端已经支持技能管理、授权和 for-Agent 列表，但开始 run 的契约只有用户 message，
缺少技能进入模型上下文的路径。固定上游 `891df72f1827454d8b353d108fe5dd2313b7e30d` 的
`app/src/lib/plugins/skill-commands.ts::useSkillCommands` 生成 `kind:chip`；
`app/src/components/channels/channel-chat.tsx::deliver` 按选择顺序追加独立 system message，
再追加用户文字。`say` 要求非空描述。所有已授予技能自动启用、把指令展开成用户文字，均不符合该语义。
这次由 Rust 解析技能slug，避免 renderer 自报系统指令成为权限真源。

HTTP `POST /api/threads/{thread_id}/runs` 和 Desktop 同一 typed command 都接受可选
`selectedSkillSlugs: ["skill-one", "skill-two"]`。缺省或空数组保持旧wire；顺序是请求身份的一部分。
最多16项为新增预算，slug沿用2–40字节ASCII小写字母/数字/连字符、首尾非连字符。重复、非法或
超量均400。message仍要求非空，不为仅选择技能的请求伪造用户文字。

新run在原事务内锁定并验证当前actor generation/撤销状态、Agent可见性与包tenant、每个当前
技能grant及技能行。Agent grant允许调用者使用该指令；个人技能的owner+Bot owner双重约束
仍用于管理和授予，不错误地要求所有使用者必须是技能作者。缺失、撤销与不可见选择统一404，
任何一项失败整次回滚，包含已临时创建的thread、membership、lease。

同事务写入有序system指令快照、用户原文与所选slug、run、started event、outbox；
用户message sequence指向system快照之后的用户消息。没有schema migration或新依赖。
上下文沿用provider的独立system角色、6MiB/4096条预算和既有工具授权路径。
没有选中技能的新会话不会自动加载已授予技能；以前已接受的system消息作为会话历史继续保留。

同runId改变用户文字、所选slug或顺序返回409；相同请求返回原receipt而不增写。
技能随后修改、删除或撤销不会重写已接受历史，也不重新派发run；失效actor的技能重试仍被拒绝。
`ThreadHistoryMessage.selectedSkillSlugs` 可选返回用户当时的原选择，读取不依赖当前grant。
消息正文保持原文；system消息依旧具有独立role，前端按其既有展示语义处理。

## 前端协作与剩余范围

前端窗口负责唯一BeginThreadRunBody生产literal及会话测试literal的最小DTO兼容补丁；
实际芯片、发送队列、历史呈现、Skills页面和整个重设计由该窗口独立实施与验收。
后端不把前端在制文件纳入这一交付，也不据此关闭完整GUI/G4/G6。

企业SSO在本机模式的能力投影、Computer/网关/原生执行生产接线、全部底层命名迁移、
其余v4闸门继续待办；本次不是完整可发布Alpha。R204已确定macOS首发，Windows E2真实Engine修复
继续作为后续Windows版本任务，不阻塞macOS独立准入。
